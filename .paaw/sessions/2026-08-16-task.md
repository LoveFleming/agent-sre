## 實作重點

**`server/routes.mjs`** — auth gate 放在 `registerRoutes` handler 最前面（單一 server 入口，不需要抽 middleware）：
- `checkApiToken()`：所有 `/api/*` 要求 `X-API-Token` header；`/api/health` 與靜態檔案豁免
- `safeTokenEqual()`：`Buffer.from` 後先比長度（長度不符直接 false，避免 `timingSafeEqual` throw），同長度才走 `crypto.timingSafeEqual` — 兩種 mismatch 路徑都是常數時間
- 失敗回 `401 { "error": "unauthorized" }`
- env 未設 → dev-mode 放行 + 每個 process 一次的警告 log
- CORS `Access-Control-Allow-Headers` 加入 `X-API-Token`（UI 之後的 fetch wrapper 需要，preflight 會檢查）

**`server/index.mjs`** — 啟動時偵測 env 未設即印醒目 dev-mode 警告（不等到第一個請求才發現）。

**測試策略**：整套測試環境設 `AGENT_SRE_API_TOKEN`、`httpJson` helper 預設帶正確 token → 既有 41 個 /api 測試（含 /api/agents、/api/tasks）自動成為「token 正確時全 API 可用」的回歸測試，不需逐一改。新增 9 個 TASK-015 case：401（無 token／長度不同錯 token／同長度錯 token，覆蓋 `timingSafeEqual` 兩條路徑）、401 時不產生 side effect、跨 endpoint 401、health 與靜態豁免、dev-mode 放行（含錯 token 也放行的一致性驗證）。

手動 smoke test 全過：401 ✓ / 正確 token 200 ✓ / health 無 token 200 ✓ / 靜態 UI 200 ✓ / dev-mode 警告 ✓。
